# Workflow de issues

- Quando o usuário indicar uma issue por `#`, leia sua descrição e comentários no repositório remoto, suas issues filhas e os comentários delas, além de outras issues relacionadas relevantes, se existirem.
- Verifique se o pedido está suficientemente definido e é implementável neste projeto. Esclareça com o usuário, durante o planejamento, quaisquer dúvidas, contradições, decisões em aberto ou impedimentos; depois disso, implemente.
- Crie ou feche issues somente quando o usuário pedir.
